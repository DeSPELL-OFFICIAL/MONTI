## 9명 종합
- **가입/로그인 ★★★★** — 패스키 재로그인 9명 전원 성공(중앙값 **7.1s**). (최초 가입은 라이브 4a에서
  9명 완료: 문자 ~3.1s / 인증 ~6.9s / 온체인 신원등록 ~12.4s / 완료 ~7s.)
- **행사 탐색 ★★★★** — 디자인·정보구조 견고, 공개 행사·상세 정상.
- **티켓 받기 — 부분 성공(★★★)** — **첫 명 온체인 발급 성공**(Ticket id=4, op success=true). 둘째부터
  실패 → 연속 받기에서 **스폰서 claim op 가 안정적으로 실리지 않는다.** 주최자 생성 op 는 드롭/만료 시
  재전송 경로가 생겼지만, **claim 에는 같은 재전송이 없어** 한 번 안 실리면 그냥 "받지 못했어요"로 끝난다.
- **내 티켓/두 번 받기(한도)/마감/승인 대기 — 미도달** — 받기 실패로 연쇄 차단 + 하니스 워커 재시작으로
  e·d·f 를 평가하지 못함(제품 결함 아님, 하니스 한계).

## 팀이 볼 단 하나
**티켓 받기(claim) op 에도 주최자 초안과 같은 드롭/만료 재전송을 붙여라.** 첫 명은 실리는데 둘째부터
안 실리는 건 스폰서 op 의 연속 포함 경합으로 보이며, 재전송이 없어 사용자에겐 그냥 실패로 보인다.
이 한 지점이 풀리면 하니스가 c(받기)→e(한도)→f(마감)→d(승인)를 그대로 재검증한다.
