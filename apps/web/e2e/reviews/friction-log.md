# 마찰 로그 (Friction Log)

대상: 프로덕션 `https://monti.despell.io`, 2026-09-26, Chromium 헤디드, 390×844, ko-KR / Asia/Seoul.

범례: **(라이브)** = 프로덕션에서 실제로 관찰함 · **(코드리뷰)** = 소스·복사 문구를 읽고 판단(라이브 미검증, reCAPTCHA 로 인증 뒤 화면은 자동 관찰 불가).

## 상위 10 마찰 (심각도 순)

1. **(라이브·치명) 가입 첫 단계에서 reCAPTCHA 이미지 챌린지.** `인증번호 받기` 를 누르면
   Firebase invisible reCAPTCHA 가 자동화 점수 미달로 "자전거/횡단보도가 포함된 이미지를 모두
   선택하세요" 챌린지로 승격된다(헤드리스·헤디드+스텔스 모두 재현). 봇은 통과 불가 →
   **자동 가입 및 그 뒤 모든 인증 흐름이 막힌다.** 실사용자도 데이터센터/VPN/새 기기에서는
   같은 이미지 챌린지를 만나 이탈 위험. → 테스트 번호에는 `appVerificationDisabledForTesting`
   훅을, 실사용에는 reCAPTCHA Enterprise 점수 튜닝을 권장.
2. **(라이브) 탐색 초기 로딩이 느리고 빈 목록.** 진입 후 2.5초에도 행사 목록 스피너가 계속
   돌았고 프로덕션에 공개 행사가 0건이라 첫 화면이 비어 보인다. 첫 방문자에게 "죽은 앱" 인상.
   → 스켈레톤 + 3초 초과 시 안내, 빈 상태 카피의 조기 노출.
3. **(라이브) 문구 중복 — 제목과 입력 라벨이 동일.** 전화 화면에서 상단 h1 "휴대폰 번호를
   입력해 주세요" 와 입력 필드 라벨이 글자까지 똑같이 두 번 나온다(코드 화면 다수가 동일 패턴:
   Screen title == Field label). 시각적 잉여. → 필드 라벨을 "휴대폰 번호" 로 축약.
4. **(코드리뷰) 행사 생성 후 "발행" 이 숨은 필수 단계.** 완료 화면은 "아직은 아무도 볼 수
   없어요… 행사 화면에서 발행해 주세요" 만 알린다. 발행은 `/org/events/:id` 의 `발행하기` →
   확인까지 눌러야 하며, 이를 모르면 아무도 티켓을 못 받는다(claim 은 Published 만 허용).
   → 완료 화면에 `지금 발행하기` 1차 액션을 직접 노출.
5. **(코드리뷰) 온체인 대기 시간(가입·발행·티켓 받기)이 최대 30초+.** `registerIdentity` 는
   블록 확정을 기다리며 "거의 다 됐어요" 한 줄만 10초 뒤 추가된다. 진행 막대가 없어 사용자는
   멈춘 것으로 오해하기 쉽다(3초 초과 단계 다수). → 예상 소요·단계 진척 강화.
6. **(코드리뷰) 승인제 경로 미완성.** `관리자 승인 후 발급` 칩은 비활성이고(플래그 off),
   주최자용 신청 관리(승인) 화면 자체가 이 빌드에 없다. 승인 대기 사용자 여정 전체가 미구현.
   → 01c 배포에 UI + `VITE_APPROVAL_MODES=on` 동반.
7. **(코드리뷰) 유료 티켓 막힘이 "곧 열려요" 로만 안내.** 유료 선택 시 만들기 버튼이 비활성이 되고
   "유료 티켓은 곧 열려요. 지금은 무료로만 만들 수 있어요" 경고만 뜬다. 정직하지만, 언제 열리는지·
   대안(무료 전환) 유도가 약하다. → 무료로 되돌리는 원탭 버튼 병기.
8. **(코드리뷰) 포스터 필수 + 크롭 모달 마찰.** 포스터가 없으면 발행 불가인데, 올리기 →
   파일 선택 → A4 크롭(끌어서/두 손가락) → "이 사진으로 정하기" 로 탭이 여러 번. 급한 주최자에겐
   부담. → 기본 프리셋만으로도 발행 허용 검토.
9. **(코드리뷰) 브라우저 한정 안내가 가입 중간에 등장.** 등록 화면에 "브라우저에서는 입장
   태그를 쓸 수 없어요. 입장은 앱에서 해요" 가 노출된다 — 웹으로 끝까지 간 사용자에게 뒤늦은
   반쪽 경험 통보. → 초기에 앱 설치 유도 배치.
10. **(라이브) 로그인 화면 정보가 얇다.** "다시 오셨네요 / 얼굴이나 지문으로 바로 들어갈 수
    있어요 / 로그인" 뿐. 이 기기에 패스키가 없을 때의 안내(가입으로)나 계정 전환 경로가 화면상
    약하다(코드엔 `noPasskey` 문구 존재하나 초기엔 안 보임). → 보조 링크 "처음이세요? 가입" 노출.

## 레이아웃/기타 (경미)

- (라이브) 390px 에서 가로 스크롤 없음, 글래스/라벤더 톤 일관, FAB·하단탭 가시성 양호.
- (라이브) 익명 상태로 `/tickets` 접근 시 `/login` 으로 정상 리다이렉트(가드 동작 확인).
- (라이브) 탐색 필터(날짜·지역·테마) 셀렉트가 화면폭에 맞게 2열/1열로 잘 배치됨.

## 자동으로 검증하지 못한 것 (정직 고지)

- reCAPTCHA 로 막힌 **가입 완료 이후 전 구간**(잠금/휴대폰 등록/완료, 행사 생성·발행, 티켓 받기,
  내 티켓, 두 번 받기 한도, 마감)은 **코드리뷰 기반**이며 프로덕션 라이브 통과를 확인하지 못했다.
- **Didit KYC**: 실제 신분증·얼굴 필요 — 자동화 불가.
- **유료 결제**: 컨트랙트 차단 — 발행 자체 불가.
- **NFC 입장**: 네이티브(안드로이드) 전용 — 웹 하니스 범위 밖("입장은 앱에서 해요").
- **승인 대기 여정**: 승인 UI·플래그가 01c 배포 전이라 미검증.
