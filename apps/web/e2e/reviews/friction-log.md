방식: Playwright 헤드리스, 390×844, ko-KR/Asia-Seoul, `monti:e2e` 캡차 우회 + WebAuthn 가상 인증자.

## 헤드라인 — 지난 3회 블로커 해소 (라이브)

고정 수수료로 멤풀에만 접수되고 채굴되지 않았다(receipt null). 이번엔 2×베이스 수수료로 실제 채굴된다.
- 관리자 스마트계정 `0x5DBdca2d…` UserOperationEvent **3건 전부 `success=true`**:
  createEvent(무료+조직) op `0x5d9a4745e234be2f0fffcc46b8b20fd010eb7a4e52aec951a879e50f5cfa9da4` @블록 65948554,
  createEvent(승인) `0x99b61cabc89c46d5a8aa416438cdfd655c51c4371c5adf926308022af2825e1c` @65948611,
  publish(승인) `0xd9201b41bb39a5a5cbd3bafbaf582983c44014e806ae817089f999460b33378c` @65948638.
- 스폰서 페이마스터 `0xf73220b082114d4e37bae8d3ab7e76cada858de4`. createEvent 번들러 tx

  실려 포함됨. (대조: 라이브 3의 스턱 op `0x3342d6ad…` 122 gwei 미채굴.)
- 인덱서 `e6b82a8`: 관리자(`0x5dbdca2d…`) 행사 4건(id 2·3·4·5), 조직 id=3. Event 4(무료)·5(승인) Published.

## 실제 제품 결함 (심각도순)

1. **[S1·라이브] 티켓 받기(claim) op 가 연속으로 안정적으로 실리지 않는다.** 무료 행사(Event 4)는 이번엔
   정상 발행됐고, **첫 이용자(서준) 받기는 온체인 발급 성공** — claim op
   `0x429c43529b31a4340ecaa5200b5416bb79b38b72687e1113e51381b848f06595` @블록 65950659 `success=true`
   → **Ticket id=4 @ Event 4** 발급(owner `0x8490af…`). 그러나 **둘째 이용자(지우) 받기는 ~3초 만에
   "티켓을 받지 못했어요. 잠시 뒤 다시 시도해 주세요"** 로 실패, 티켓 미발급. 주최자 초안에는 드롭/만료 op
   재전송이 붙었지만 **claim 경로엔 같은 재전송이 없어** 한 번 안 실리면 그대로 실패로 끝난다. 연속 받기의
   스폰서 op 포함 경합으로 보이며, 이 지점이 c 이후(e·d·f) 전부를 막았다.
2. **[S1·하니스] `publishEvent` 가 생성 직후 인덱서 지연 창을 "이미 발행됨"으로 오판.** 무료 행사를 만든
   직후 `/org/events/{id}` 로 가면 인덱서가 아직 그 초안을 반영 못 해 `발행하기` 버튼이 잠깐 안 보인다.
   기존 로직은 "버튼 없음 ⇒ 이미 발행됨"으로 조기 반환(2.6s)해 **행사가 Draft 로 남고 이후 모든 받기가
   실패**했다(라이브 4a 에서 관측: Event id=2 가 Draft 로 잔류). → **하니스 수정**(앱 무수정):
   `apps/web/e2e/utils/organizer.ts` `publishEvent` 를 "초안의 `발행하기` 버튼이 뜰 때까지 폴링(최대 120s)한
   뒤 발행"으로 교체. 수정 후 라이브 4b 에서 무료 행사가 실제 Published(발행 12.2s)되고 첫 받기가 성공했다.
   (실사용자 함의: 방금 만든 행사가 대시보드에 잠깐 안 뜰 수 있음 — 인덱서 지연.)
3. **[S2·하니스 설계] 한 시나리오가 실패하면 뒤 시나리오를 평가할 수 없다.** Playwright 는 테스트 실패 후
   워커를 재시작(모듈 재임포트)하는데, `10-personas.spec.ts` 는 `describe` 스코프 변수(`admin`/`users`/
   이벤트 id)로 시나리오 간 상태를 공유한다. b+c 가 실패하자 e·d·f 는 `admin`/`users` 가 `undefined`,
   `approvalEventId` 가 `""` 인 채로 즉시 `TypeError`/빈값으로 떨어졌다(1~7ms). 즉 **e·d·f 는 실패가 아니라
   "미평가"** 다. 개선안: 이벤트 id 를 디스크에 퍼시스트하거나 시나리오를 단일 test 로 합쳐 워커 재시작에도
   상태가 살아남게.

  재시작돼 도달/평가 못 함(승인 행사 Event 5 는 발행까지는 됨).

## 팀이 고쳐야 할 단 하나
**티켓 받기(claim) op 에도 주최자 초안과 동일한 드롭/만료 재전송을 붙여라.** 첫 명은 실리는데 둘째부터
안 실리는 건 스폰서 op 연속 포함 경합이며, 재전송이 없어 사용자에겐 그냥 실패로 보인다. 이 한 지점이
풀리면 하니스가 c→e→f→d 를 그대로 재검증한다(그 전에 friction #3 상태공유도 손보면 완주 관측이 쉬워진다).
